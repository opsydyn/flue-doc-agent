This Starlight section is a **worked example** of Diátaxis. The subject stays the same throughout —
using [Flue](https://flueframework.com/) and the `doc-freshness` agent in this repository — while the
reader need changes.

That change in reader need is exactly what the four Diátaxis quadrants capture.

## The four types

| Type | Reader need in this repo | Start here when you want to… |
| --- | --- | --- |
| **Tutorial** | First successful run | get `flue run doc-freshness` working locally |
| **How-to guide** | Task completion | run the webhook server, narrow a scan, switch modes |
| **Reference** | Exact facts | check commands, payload fields, tools, env vars, result shapes |
| **Explanation** | Mental model | understand why this repo uses Flue, Effect, Varlock, and a deterministic default |

The key idea is simple: the same system should not be documented the same way for every reader.
A first run needs a guided path. A day-two problem needs directions. A coding session needs facts.
An architectural question needs context.

## Why this section exists

Before this rewrite, the Diátaxis pages in this repo mostly described the framework itself. That was
useful, but it did not show people how to **use Flue here**. These pages now do both jobs:

- they explain the quadrants implicitly by using them well
- they document the real entry points for this repository
- they keep Flue usage, agent usage, reference data, and design reasoning separated

If you want the shortest path to value, start with the tutorial. If you already know what you are
trying to achieve, jump directly to the how-to guide or the reference.
